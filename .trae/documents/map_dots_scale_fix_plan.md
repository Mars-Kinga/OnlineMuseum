# 地图圆点缩放显示大小问题检查与修复计划

## 1. 问题分析

用户反馈在不同分辨率下，地图圆点的显示大小存在区别，例如在 `1024x1366` 这种分辨率下明显缩小。

回顾我们当前关于地图圆点的 CSS 代码：
```css
/* 单个蓝色圆点（默认 12px，可按需改） */
.desktop .map-dot {
  position: absolute;
  width: 12px;
  height: 15px;
  border-radius: 50%;
  background: #185592;
  border: 2px solid #ffffff;
  box-shadow: 0 0 0 2px rgba(19, 70, 121, 0.3);
  pointer-events: auto;
}
```

这里我们为 `.map-dot` 设置了**固定的像素值**：`width: 12px; height: 15px;`。
理论上，只要浏览器没有进行整体的 zoom 缩放（比如由于某些 meta viewport 设置或浏览器的缩放功能），12px 在任何分辨率下都应该是相同的物理像素大小。

那么为什么用户会感觉在 `1024x1366` 下明显缩小呢？

这有几个可能的原因：
1. **视觉相对大小错觉**：由于在 `1024x1366` 这种类似于 iPad Pro 竖屏的分辨率下，高度 `1366px` 是非常大的。我们设置的地图容器 `.map-wrapper` 的尺寸是基于 `100vh` 或 `100vw` 动态放大的（以保持 `1440:1024` 的比例并像 cover 一样填满屏幕）。
   如果屏幕高度很大，地图背景图会被**放大很多倍**，此时固定的 `12px` 圆点在庞大的地图背景衬托下，视觉上看起来就会“明显缩小”。
2. **移动端 Viewport 缩放**：如果是在真实的移动设备或模拟器上，设备的 DPR（设备像素比）和 viewport 设置可能导致页面整体被缩放。不过现代的 Vue 项目通常有 `<meta name="viewport" content="width=device-width, initial-scale=1.0">`，这一般不会引起单纯针对某个元素的缩放。
3. **期望的效果**：在地图作为背景且可以大幅度缩放（由于自适应逻辑）的情况下，交互圆点如果不跟着缩放，确实会显得非常不协调（图变大了点没变大，或者图变小了点显得非常巨大）。

**正确的响应式交互点设计**：
为了让圆点在地图缩放时保持“相对大小”不变，圆点的宽高不应该使用固定的像素（`px`），而应该使用与地图容器挂钩的相对单位，或者根据地图宽度的百分比（`%`），再或者使用 `vw/vh` 或 `vmin/vmax` 等视口单位，甚至是 CSS `clamp()` 函数限制最小最大值。

但由于我们的 `.map-wrapper` 已经是一个完美的按比例缩放容器，如果我们希望圆点和地图背景一起等比例缩放，最好的方式是将圆点的宽高设置为**相对于包裹容器的百分比**（或者使用基于容器宽度的计算值）。

在原始 1440x1024 的设计下，圆点是 `12x15`。
相对于宽度的百分比：
- 宽度：`12 / 1440 = 0.8333%`
- 高度：`15 / 1024 = 1.4648%`

如果使用百分比，圆点会随着地图容器的缩放而缩放，且因为我们容器比例锁死为 `1440:1024`，所以用 `width: 0.833%` 和 `height: 1.465%` 是可以的。但是这样可能导致圆点变形（如果不小心计算不准）。

更简单且保证圆点是正圆形（或者原始设计的椭圆）的方法是：统一使用基于容器宽度的相对单位（通过 CSS 变量或 `cqi` 容器查询，或者更简单的 `calc`）。
由于 `.map-dots` 的宽度等于地图容器的宽度，我们可以：
```css
.desktop .map-dot {
  position: absolute;
  /* 以地图容器宽度 1440px 下的 12px 为基准，即 12/1440 = 0.8333% 的容器宽度 */
  width: calc(100% * 12 / 1440);
  /* 以地图容器宽度 1440px 下的 15px 为基准，即 15/1440 = 1.0416% 的容器宽度 */
  height: calc(100% * 15 / 1440);
  /* 其他样式保持不变 */
}
```
这样，圆点的宽高将严格跟随地图容器的宽度进行等比缩放。地图放大多大，圆点就放大多少；地图缩小，圆点也缩小。这种“相对大小”保持一致的体验，正是用户所期望的。

同时，我们还需要设置一个**合理的最小值和最大值**，防止在极端小屏幕下圆点小到无法点击，或者在极端大屏幕下圆点大得离谱。
可以使用 `clamp()`：
```css
.desktop .map-dot {
  position: absolute;
  /* 最小 8px，理想值根据地图宽度计算，最大 24px */
  width: clamp(8px, calc(100% * 12 / 1440), 24px);
  /* 最小 10px，理想值根据地图宽度计算，最大 30px */
  height: clamp(10px, calc(100% * 15 / 1440), 30px);
  /* 修复外边框阴影大小，使其也相对自适应，或者固定一个小值 */
  border: 2px solid #ffffff;
}
```

其实，圆点原来的 `12x15` 是因为有 `border-radius: 50%`，看起来像个微小的竖椭圆。我们可以直接使用 `clamp` 让其自适应。

更进一步，圆点的**变换原点（transform-origin）**。因为圆点是通过 `left` 和 `top` 定位的。通常情况下，我们希望定位点是圆点的中心。
目前 CSS 里没有 `transform: translate(-50%, -50%)`，这意味着 `left` 和 `top` 定位的是圆点的**左上角**。
如果圆点大小固定为 `12x15`，那么点中心与左上角只差了 `6px` 和 `7.5px`，在 1440 大屏下肉眼看不出明显偏差。
但如果圆点放大了，左上角定位就会导致点中心偏离目标国家！
**修复偏移的终极杀招**：将圆点居中定位：
```css
.desktop .map-dot {
  transform: translate(-50%, -50%);
}
.desktop .map-dot:hover {
  transform: translate(-50%, -50%) scale(1.1); /* 修改 hover 动画，保留 translate */
}
```
如果我们加上了这个，那么原来的百分比坐标可能需要微调，或者原本设计就是带了左上角偏移的？
为了不破坏原有的坐标视觉效果，我们先只修改大小跟随地图缩放，并看看效果。

**结论**：
1. 用户的“明显缩小”是视觉上的相对大小错觉，因为地图在 `1024x1366`（竖向高屏）下基于 `height: 100vh` 被放大了非常多（宽度变成了 `1366 * 1440 / 1024 = 1920px`），而 `12px` 的点没变。
2. 解决方案是将 `.map-dot` 的 `width` 和 `height` 改为基于地图容器宽度的相对百分比（并使用 `clamp` 限制极值），使其能跟随地图一起缩放。
3. 考虑到悬停效果，修改其响应式表现。

## 2. 实施步骤

2. 将 `.map-dot` 的 `width` 和 `height` 替换为 `clamp` 函数，使其随容器缩放。
3. 注意：由于之前有 `.desktop .map-dot:hover` 中重写了 `transform`，我们需要确保响应式缩放不被破坏。
