# 地图圆点缩放与拉长问题彻底修复计划

## 1. 问题复盘

在上一次修改中，为了让地图圆点的大小跟随地图的缩放比例，我们为 `.desktop .map-dot` 做了如下设置：
```css
.desktop .map-dot {
  position: absolute;
  /* 宽度取包裹层宽度的百分比，并用 clamp 限制大小 */
  width: clamp(8px, calc(100% * 12 / 1440), 24px);
  height: auto;
  aspect-ratio: 12 / 15;
  min-height: 10px;
  max-height: 30px;
  transform: translate(-50%, -50%);
}
```

用户反馈了两个问题：
1. **其他分辨率下圆点出现了拉长的问题**。
2. **在 1024x1366 下，圆点仍然明显缩小**。

### 为什么会出现拉长（变形）？
在绝对定位下（`position: absolute`），虽然我们设置了 `aspect-ratio: 12 / 15`，但同时存在 `height: auto` 和 `min-height / max-height` 的限制。
当容器的宽度变化时，计算出的 `width` 如果被 `clamp` 限制在了边界（例如最大 24px），那么 `width` 是固定的。理论上 `aspect-ratio` 应该能保持高度为 `24 * 15 / 12 = 30px`。
但是，由于绝对定位元素的各种兼容性或上下文影响，有些浏览器可能并未完美按照 `aspect-ratio` 处理，或者被 `max-height` 干扰。
另外，圆点的形状很大程度上依赖于其原始设计：由于原始尺寸是 `12x15`，它本来就是一个**竖向的椭圆形**（因为 `border-radius: 50%` 应用在一个宽小于高的盒子上）。在不同分辨率和计算逻辑下，椭圆的拉伸会显得特别突兀（尤其是如果长宽比失效变成其他比例时）。

### 为什么在 1024x1366 下仍然明显缩小？
在 `1024x1366` 分辨率下，地图是被当作 `cover` 模式铺满的：
- 屏幕高 `1366`，基于高度计算出的理论宽度是 `1366 * 1440 / 1024 = 1920.9px`。
- 因为这个宽度大于屏幕宽度（`1024`），所以地图包裹层 `.map-wrapper` 的实际尺寸就是 `1920.9px x 1366px`。

在这个大容器下，如果用百分比计算宽度：
`calc(1920.9px * 12 / 1440) = 16px`。
然后 `clamp(8px, 16px, 24px)` 会让它变成 `16px`。

问题来了：地图从 `1440` 放大到了 `1920`（放大了 1.33 倍），圆点从 `12px` 放大到了 `16px`（也是 1.33 倍）。**在数学和物理比例上，它是完全等比例缩放的**。

那么为什么用户**仍然觉得明显缩小**？
这是因为在竖屏模式下，用户看到的是一个截取的屏幕（宽度只有 1024，高度极长），虽然地图实际很大，但用户视野被限制了。或者用户期望的是，无论屏幕怎么变，圆点在屏幕上的**绝对大小**（物理尺寸）应该保持一个比较合理的“肉眼可见”的范围，而不是因为背景被放大，点也仅仅是微弱地等比例放大。特别是当背景因为 `cover` 被放大到很大时，一个 `16px` 的点在 `1366px` 的高屏上显得非常渺小。

更重要的是，我们在 `clamp` 中设置了 `max-width: 24px`。如果地图容器被放大得非常非常大，圆点最多也只能到 24px。

## 2. 彻底的解决思路

放弃复杂的百分比和 `aspect-ratio` 混合计算。既然在原始设计中，地图大小为 1440x1024 时，圆点大小为 `12x15`，我们直接使用 **vw/vh 等视口单位或容器查询** 似乎并不好控制用户的“主观感觉”。

既然用户觉得“缩小”，且觉得“拉长”（椭圆拉伸问题），我们应该：

1. **修正形状**：不要用 12x15 的椭圆了。在缩放中，椭圆极易因为计算偏差显得“拉长”或变形。**把圆点统一改成正圆形**，比如 `15x15`，这样视觉上更稳定，且不再需要 `aspect-ratio`，直接设置宽高相等。
2. **使用更激进/更可见的相对单位，或直接调大基础尺寸**：如果用户觉得 1024x1366 下缩小，我们可以使用基于容器尺寸但带有一个更大基础值的 `clamp`，甚至可以直接**固定为一个舒适的物理像素大小范围**。很多现代网页中，地图上的锚点其实是**不随地图缩放而无限缩放的**（比如高德/Google地图，你放大地图，大头针图标的大小是不变的）。
   之前我们把它改成随容器缩放，可能违背了这种常见的 UI 习惯，导致缩放比例不对时显得很奇怪。
   
如果我们**固定圆点的绝对物理大小**，无论地图怎么缩放，圆点始终是清晰可见的（比如 `16x16` 或 `20x20`），这样既不会“明显缩小”，也不会“拉长变形”。
为了兼顾不同设备，我们可以根据屏幕宽度（而非地图背景宽度）做简单的媒体查询响应式，或者直接用固定的像素。

**核心方案**：
1. 取消基于地图宽度 `%` 的计算。
2. 将 `.map-dot` 设置为**正圆形**（如默认 `16px x 16px`）。
3. 使用 `clamp` 确保它在移动端不至于太大，在桌面端不至于太小（例如 `clamp(14px, 1.5vw, 20px)`），这个大小是相对于**屏幕视口**的，而不是相对于地图背景那可能无限延伸的虚拟容器的。
4. 保持 `transform: translate(-50%, -50%)` 确保中心点对齐。

这样：
- 在 1024x1366 下，`1.5vw` 是 `15.3px`，它在屏幕上始终占据这么大的物理空间，不会因为背后的地图放大了 3 倍而显得像蚂蚁一样。
- 宽高完全相等，配合 `border-radius: 50%`，永远是完美的正圆，绝对不会被拉长。

## 3. 实施步骤

1. 在 `Desktop.vue` 的 CSS 中，修改 `.desktop .map-dot` 的样式。
2. 移除 `aspect-ratio` 和百分比计算。
3. 设置 `width` 和 `height` 为相等的固定值或相对于视口的 `clamp`（例如：`width: 16px; height: 16px;`，或者 `width: clamp(14px, 1.5vw, 20px); height: clamp(14px, 1.5vw, 20px);`）。为了绝对稳定，我建议先用一个看起来比较舒适的像素范围：`width: max(16px, 1.2vw); height: max(16px, 1.2vw);`。
4. 清理旧的 `max-height` 等冗余属性。
5. 验证效果。
